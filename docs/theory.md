# Ответы на теоретические вопросы

Цитатой перед каждым ответом — формулировка вопроса из задания.

## Строгий режим

> Что такое «строгий режим»? Для чего он нужен?

Директива `'use strict'` в начале файла или функции включает более строгий
вариант семантики языка: присваивание в необъявленную переменную бросает
`ReferenceError`, `this` в обычном вызове функции равен `undefined`, а не
глобальному объекту, запрещены дубли имён параметров и восьмеричные литералы
вида `0644`. Нужен, чтобы ошибки падали сразу, а не превращались в молчаливое
странное поведение.

Модули ES и тела классов работают в строгом режиме всегда, поэтому в
современном коде директиву писать не нужно.

## var, let, const

> Переменные — в чём отличие var, let, const? Когда и что предпочтительнее
> применять?

| | `var` | `let` | `const` |
| --- | --- | --- | --- |
| Область видимости | функция | блок | блок |
| До объявления | `undefined` | ошибка (TDZ) | ошибка (TDZ) |
| Повторное объявление | можно | ошибка | ошибка |
| Переприсваивание | можно | можно | нельзя |

`var` на верхнем уровне скрипта ещё и создаёт свойство глобального объекта.

По умолчанию `const` — он показывает, что ссылка не меняется. `let` там, где
значение действительно переприсваивается (счётчики, накопители, переменная в
`for`). `var` в новом коде не нужен.

`const` запрещает переприсваивание, но не мутацию: у объекта под `const` можно
менять свойства.

## Операторы сравнения

### `==` против `===`

> В чём отличие `==` от `===`; `!=` от `!==`?

`===` сравнивает без приведения типов: разные типы — сразу `false`. `==`
сначала приводит операнды к общему типу и только потом сравнивает. `!=` и
`!==` — их отрицания с теми же правилами.

В коде разумно всегда использовать `===`, кроме проверки «пусто ли значение»:
`value == null` истинно и для `null`, и для `undefined`.

### `'01' == 1` и `'01' === 1`

> Что будет в результате: `'01' == 1` и `'01' === 1`? Почему?

```js
'01' == 1;  // true
'01' === 1; // false
```

При сравнении строки с числом строка приводится к числу: `Number('01')` — это
`1`, отсюда `true`. Строгое сравнение приведения не делает, а `string` и
`number` — разные типы.

### `null === undefined` и `null == undefined`

> Что будет в результате: `null === undefined` и `null == undefined`? Почему?

```js
null === undefined; // false
null == undefined;  // true
```

Типы разные, поэтому строгое сравнение ложно. У нестрогого есть отдельное
правило: `null` и `undefined` равны друг другу и не равны ничему больше,
приведение к числу здесь не выполняется.

### `null` и ноль

> Что будет в результате: `null > 0`; `null == 0`; `null >= 0`? Почему?

```js
null > 0;  // false
null == 0; // false
null >= 0; // true
```

Операторы сравнения `>` и `>=` приводят `null` к числу `0`, поэтому `0 > 0`
ложно, а `0 >= 0` истинно. Оператор `==` работает по правилу из предыдущего
пункта: `null` сравнивается только с `undefined` и к нулю не приводится.
Отсюда несогласованная на вид пара `null >= 0` — `true` при `null == 0` —
`false`.

### `undefined` и ноль

> Что будет в результате: `undefined > 0`; `undefined < 0`; `undefined == 0`?
> Почему?

```js
undefined > 0;  // false
undefined < 0;  // false
undefined == 0; // false
```

При сравнении `undefined` превращается в `NaN`, а любое сравнение с `NaN`
ложно — поэтому `false` в обе стороны. Нестрогое равенство снова не приводит
типы: `undefined` равен только `null` и самому себе.

## Функции в переменных

> Функции: можно ли сохранить функцию в переменную?

Да, функция в JavaScript — обычный объект, её можно положить в переменную,
передать аргументом, вернуть из другой функции или сохранить в массив.

```js
const double = function (value) {
  return value * 2;
};

const triple = (value) => value * 3;
```

Разница с объявлением `function double() {}` в поднятии: объявление доступно до
своей строки в коде, функция в переменной — нет.

## Подтверждение действия через колбэки

> Функции-колбэки: напишите функцию, которая реализует подтверждение
> определённого действия (например, «вы точно хотите удалить выбранный
> элемент?»). В качестве параметров функция должна принимать: вопрос;
> функцию-колбэк, вызываемую если пользователь подтвердит действие;
> функцию-колбэк, вызываемую, если пользователь отклонит действие. Для
> подтверждения пользователем используйте стандартную функцию `prompt`.

```js
function confirmAction(question, onConfirm, onCancel) {
  const answer = prompt(`${question} (да/нет)`, 'да');

  // prompt возвращает null, если пользователь нажал «Отмена».
  if (answer !== null && answer.trim().toLowerCase() === 'да') {
    onConfirm();

    return;
  }

  onCancel();
}

confirmAction(
  'Вы точно хотите удалить выбранный элемент?',
  () => console.log('Элемент удалён'),
  () => console.log('Удаление отменено'),
);
```

## Объекты, методы, `this`

> Объекты, методы объектов, this. Что такое this? Приведите пример потери this.
> Приведите пример решения проблемы потери this через привязку контекста и
> стрелочные функции.

`this` — ссылка на объект, в контексте которого вызвана функция. Определяется
не местом объявления, а способом вызова: при `obj.method()` это `obj`.

Потеря контекста происходит, когда метод отрывают от объекта:

```js
const user = {
  name: 'Артём',
  sayHi() {
    console.log(this.name);
  },
};

const sayHi = user.sayHi;

sayHi(); // TypeError: this — undefined
setTimeout(user.sayHi, 100); // то же самое: вызов идёт не через user
```

Первое решение — привязать контекст явно:

```js
const boundSayHi = user.sayHi.bind(user);

setTimeout(boundSayHi, 100); // Артём
```

Второе — обёртка из стрелочной функции: у неё нет своего `this`, она берёт его
из внешней области, а вызов внутри остаётся вызовом через точку:

```js
setTimeout(() => user.sayHi(), 100); // Артём
```

По той же причине стрелочную функцию не стоит делать методом объекта, если в
ней нужен `this` этого объекта: она возьмёт `this` из места объявления, а не из
вызова.

## setTimeout и setInterval

> Планирование: setTimeout и setInterval. Для чего они используются? В чём
> отличие setInterval от рекурсивного setTimeout? Отмена timeout-а и
> interval-а.

`setTimeout` откладывает вызов один раз, `setInterval` повторяет его с заданной
периодичностью. Обе возвращают идентификатор таймера, по которому вызов
отменяется — `clearTimeout(id)` и `clearInterval(id)`. В React такая отмена
обязательна в функции очистки эффекта, иначе таймер продолжит работать после
размонтирования.

```js
const timeoutId = setTimeout(tick, 1000);

clearTimeout(timeoutId);

const intervalId = setInterval(tick, 1000);

clearInterval(intervalId);
```

`setInterval` отсчитывает интервал от начала предыдущего запуска, поэтому время
работы самой функции входит в паузу: если код выполняется дольше интервала,
пауза между вызовами сокращается почти до нуля. Рекурсивный `setTimeout`
планирует следующий запуск после завершения текущего — задержка соблюдается
целиком, и её можно менять на каждом шаге, например увеличивать при повторных
неудачных запросах.

```js
const poll = () => {
  fetchData();

  setTimeout(poll, 1000);
};

setTimeout(poll, 1000);
```

## Что такое TypeScript

> Что такое TypeScript? Для чего введён? В чём отличие от JS?

Надмножество JavaScript со статической типизацией: любой валидный JS —
валидный TS. Компилятор проверяет типы и стирает их, на выходе получается
обычный JS, который и исполняет браузер.

Введён, чтобы ошибки вида «опечатка в имени свойства» или «сюда пришёл
`undefined`» находились до запуска. Попутно типы дают точное автодополнение,
безопасный рефакторинг и описывают контракты вместо комментариев.

Главное практическое отличие от JS: проверки существуют только на этапе
сборки, в рантайме их нет. Данные, пришедшие из сети, приходится проверять
самостоятельно.

## Базовые типы

> Расскажите про базовые типы TypeScript.

- Примитивы: `string`, `number`, `boolean`, `bigint`, `symbol`, `null`,
  `undefined`.
- Массивы и кортежи: `string[]` или `Array<string>`, `[number, string]` с
  фиксированной длиной и порядком.
- Объекты: литеральный тип вида `{ id: string; count: number }`.
- Литеральные типы и объединения: `'ru' | 'en'`, `number | null`.
- Пересечения: `Base & { id: string }`.
- `any` отключает проверку типа целиком; `unknown` — безопасный аналог, с
  которым ничего нельзя сделать без сужения типа.
- `void` — функция ничего не возвращает, `never` — не возвращает вовсе
  (бросает исключение или зацикливается).

## Обобщённые типы

> Расскажите про обобщённые типы (generics) в TypeScript, приведите пару
> примеров.

Generics позволяют описать тип, параметризованный другим типом: связь между
входом и выходом сохраняется, а конкретный тип подставляется в месте вызова.

```ts
const first = <TItem>(items: TItem[]): TItem | undefined => items[0];

first([1, 2, 3]); // number | undefined
first(['a']); // string | undefined
```

Ограничение через `extends` сужает допустимые параметры — здесь ключ обязан
принадлежать объекту, поэтому тип результата известен точно:

```ts
const pick = <TData, TKey extends keyof TData>(
  data: TData,
  key: TKey,
): TData[TKey] => data[key];
```

Так же параметризуются интерфейсы — типичный случай — обёртка ответа API:

```ts
interface ApiResponse<TData> {
  data: TData;
  status: number;
}

type WordsResponse = ApiResponse<Word[]>;
```

## type и interface

> Расскажите про типы (type) и интерфейсы (interface) в TypeScript, в чём их
> отличие?

`interface` описывает форму объекта или класса. `type` — псевдоним для любого
типа, включая объединения, кортежи, примитивы и вычисляемые типы.

```ts
interface User {
  id: string;
  name: string;
}

type Role = 'admin' | 'user';
type UserWithRole = User & { role: Role };
```

Отличия на практике два. Интерфейсы объединяются при повторном объявлении
(declaration merging), поэтому ими удобно расширять типы из чужих библиотек;
у `type` повторное объявление — ошибка. И только `type` умеет описывать
объединения, кортежи и mapped-типы.

Разумный ориентир: объектные контракты и пропсы — `interface`, всё остальное —
`type`.

## Необязательные свойства

> Как сделать ряд свойств интерфейса необязательными? Как сделать все свойства
> интерфейса необязательными?

Отдельные свойства помечаются знаком `?`:

```ts
interface Profile {
  name: string;
  phone?: string;
}
```

Все свойства сразу делает необязательными утилита `Partial`:

```ts
type ProfileDraft = Partial<Profile>;
```

Обратная операция — `Required<Profile>`. `Partial` работает на один уровень
вложенности: для вложенных объектов нужен свой рекурсивный тип.

## Зачем нужен Omit

> Для чего нужен тип `Omit` в TypeScript?

`Omit<Type, Keys>` строит новый тип из существующего, выбрасывая указанные
ключи. Нужен, чтобы не дублировать описание, когда тип почти совпадает с уже
существующим.

```ts
type PublicUser = Omit<User, 'password'>;
```

Частый случай в React — пропсы компонента поверх атрибутов элемента, где часть
атрибутов задаётся внутри и наружу не выставляется:

```ts
type ButtonProps = Omit<ComponentProps<'button'>, 'type'> & {
  variant: 'primary' | 'secondary';
};
```

Парная утилита `Pick` делает обратное — оставляет только перечисленные ключи.

## Перегрузка функций

> Возможно ли в TypeScript перегрузить функцию?

Да, через сигнатуры перегрузки: несколько объявлений и одна реализация под
ними. Вызов разрешается по объявлениям, сама реализация в разрешении не
участвует и наружу не видна, поэтому её сигнатура должна покрывать все
варианты.

```ts
function parseDate(value: number): Date;
function parseDate(value: string): Date | null;
function parseDate(value: string | number): Date | null {
  const date = new Date(value);

  return Number.isNaN(date.getTime()) ? null : date;
}

parseDate(0); // Date
parseDate('2026-09-10'); // Date | null
```

Это чисто типовой механизм: в собранном JS остаётся одна функция, и разбирать
аргументы приходится вручную. Если варианты отличаются только типом одного
параметра, объединение или generic обычно читается лучше перегрузки.
